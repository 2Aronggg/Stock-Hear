# 개발 규칙

## 공통 규칙

1. TypeScript strict mode를 유지한다.
2. `any` 타입을 사용하지 않는다.
3. 실제 API 키, secret, access token, approval key를 코드에 쓰지 않는다.
4. 매수, 매도, 계좌조회, 투자추천 기능을 구현하지 않는다.
5. 한국투자증권 공식 필드를 모르면 추측해서 매핑하지 않는다.
6. 기능 변경 시 README 또는 docs도 함께 갱신한다.
7. 파일을 늘리기보다 MVP가 이해하기 쉬운 단위로 유지한다.

## 프론트엔드 규칙

- 프론트엔드는 우리 백엔드 WebSocket에만 연결한다.
- `VITE_` 환경변수에는 공개 가능한 서버 주소만 둔다.
- 버튼으로 가능한 기능은 키보드로도 가능해야 한다.
- 색상만으로 상승과 하락을 표현하지 않는다.
- 페이지 로드 직후 자동으로 소리를 재생하지 않는다.
- 사용자의 명시적 동작 이후 Web Audio API를 사용한다.
- 실시간 가격을 매번 `aria-live`로 읽지 않는다.
- 연결 상태, 오류, 명령 결과처럼 중요한 정보만 화면낭독기에 전달한다.

## 소리화 규칙

- 가격 상승은 기준음보다 높은 음으로 표현한다.
- 가격 하락은 기준음보다 낮은 음으로 표현한다.
- 보합은 중립음으로 표현한다.
- 거래량이 많을수록 음량을 키우되 최대 음량을 제한한다.
- 체결빈도는 추후 일정 시간 단위의 리듬으로 표현한다.
- 모든 체결을 빠짐없이 소리로 재생하려 하지 않는다. 사용자가 이해할 수 있는 속도를 우선한다.

## 음성 명령 규칙

- 항상 듣는 방식이 아니라 버튼을 누르고 말하는 방식을 사용한다.
- 현재가, 등락률, 거래량, 소리 시작, 소리 멈춤처럼 명확한 명령만 처리한다.
- 지원하지 않는 명령은 추측하지 않고 안내한다.
- 투자 추천으로 볼 수 있는 명령은 처리하지 않는다.
- 사용자의 음성 녹음 파일을 저장하지 않는다.

## 백엔드 규칙

- `process.env`는 `apps/server/src/config.ts`에서만 직접 읽는다.
- 한국투자증권 인증은 서버에서만 수행한다.
- 원본 API 응답 전체를 프론트엔드로 보내지 않는다.
- 원본 체결 메시지는 `RealtimeTrade`로 변환한 뒤 전달한다.
- 잘못된 WebSocket 메시지는 서버를 중단하지 않고 error 응답으로 처리한다.
- 비밀값은 로그와 오류 메시지에 포함하지 않는다.
